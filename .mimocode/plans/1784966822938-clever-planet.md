# Webore Landing Page: Performance Fix + Vibrant Redesign

## Summary

Three-part overhaul of the Webore homepage (`public/` only, no server changes):

1. **Task 1** — Optimize the 240-frame PNG hero (~316MB) down to 80 compressed frames with lazy loading
2. **Task 2** — Add vibrant accent colors, gradient tokens, mesh backgrounds, scroll reveals, magnetic CTA buttons
3. **Task 3** — Add social proof logo marquee, testimonial cards, enhanced differentiators, and a before/after comparison section

**Constraints**: No server/, Prisma, auth, or chat changes. Keep responsive. Respect `prefers-reduced-motion`.

## TASK 1 — Hero Performance Fix (Critical)

### Problem
- `hero-scroll.js` preloads ALL 240 PNGs totaling **316MB** before showing anything
- Every frame is loaded as a separate HTTP request simultaneously via `new Image()` — catastrophic on slow connections
- The loader bar shows frame count, not bytes loaded

### Solution: Reduce Frames + Phased Lazy-Load + LRU Buffer

**Step 1: Create optimized frame set (80 frames)**
- Copy every 3rd frame from the original 240 into `public/assets/frames-opt/`
- This reduces the total payload from ~316MB to ~105MB (same per-frame size, 1/3 the frames)
- Further compress: convert PNGs to WebP in place (saves ~60% more → ~42MB total)
- Use a bash script to do both: select frames + convert to WebP

**Step 2: Rewrite `public/js/hero-scroll.js` loading strategy**
- Change `TOTAL_FRAMES` from 240 to 80
- Change `FRAME_BASE` to `/assets/frames-opt/`  
- Change `FRAME_EXT` from `.png` to `.webp`
- Interpolate the scroll math: `frameIndex = Math.round(progress * (TOTAL_FRAMES - 1))` — no change needed, just works with 80

Replace the "load all at once" strategy with **phased lazy-load + LRU buffer**:
1. **Phase 1 (critical path)**: Load frames 0–9 (first 10%) synchronously, update loader bar with real progress
2. **Phase 2 (idle loading)**: Use `requestIdleCallback` (with `setTimeout` fallback) to load frames 10–79 in the background while user is on frame 0
3. **LRU buffer**: Keep only the most recent 15 rendered frames in `frames[]`; evict older ones and re-fetch on demand if user scrolls back
4. **Loader**: Show "Loading experience..." during Phase 1, then hide loader once first 10 frames are ready (don't wait for all 80)

**Step 3: Add bytes-based progress bar**
- Track `loadedCount` during Phase 1, set `loaderBar.style.width` as percentage
- After Phase 1 completes, immediately hide loader and start scroll listener
- Phase 2 loads happen silently in background
